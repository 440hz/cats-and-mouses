# Git workflow (CATS AND MOUSES)

По просьбе «закоммить и пушнуть» выполняй строго по порядку:

1. Подними **patch-версию** в `android/build.gradle.kts` (`versionName`), например 1.0.0 → 1.0.1.
2. Добавь запись в `CHANGELOG.md`: новая секция версии по формату Keep a Changelog (тип изменения и краткое описание).
3. Создай ветку `1.0.1/<тип>/<суть>` — `<тип>`: `feature` | `docs` | `bugfix`; `<суть>` — краткое имя работы латиницей через дефис.
4. Закоммить изменения (сообщение краткое, по-русски), включая `android/build.gradle.kts` и `CHANGELOG.md`.
5. Запушь ветку **только в `origin`**: `git push -u origin <ветка>`.
6. Переключись на `master` (`git checkout master`) и смержи ветку.
7. Запушь `master` в `origin`: `git push origin master`.

## Пуш в GitHub (только по команде «пуш в github»)

В течение дня пуши выполняются **только в `origin`** (Gitea). GitHub — отдельный remote (`github`), используемый ТОЛЬКО как публичное зеркало. Пуш туда происходит **только по явной команде пользователя** «пуш в github». Дополнительного поднятия версии не требуется — это просто синхронизация.

По команде «пуш в github» пушится **только `master`**, всегда с явным указанием ветки:

```
git push github master
```

ЗАПРЕЩЕНО использовать:
- `git push github` (без ветки — пушнет только текущую ветку)
- `git push github --all` (зальёт все ветки)
- `git push github --mirror` (зальёт всё + теги)

## Важно

- Номер версии в имени ветки — всегда новая версия после поднятия patch.
- Не понижай версии зависимостей, не трогай `local.properties` и `opencode.json`.
- Перед коммитом проверяй статус и дифф (`git status`, `git diff`) — стейдж только нужные файлы.
- Remote: `origin` (Gitea `<gitea-host>:3000`), `github` (https://github.com/440hz/cats-and-mouses.git). Обычный пуш — только в `origin`; в `github` — только master по команде «пуш в github».
- `push.default=current` установлен глобально — пуш без указания ветки пушнет только текущую, но в github ветка указывается всегда явно.
