# tests/ — dev-анализ карт (Python, не входит в игровую сборку)

Здесь живут Python-скрипты для проверки карт (`assets/maps/` и эталонов). В APK/jar/dist
не попадают: это не source set Gradle и не `assets/`. Kotlin-тесты игры живут отдельно —
в `core/src/test/kotlin` (JUnit5 + headless LibGDX, запуск `.\gradlew core:test`); они
используют те же фикстуры `tests/fixtures/` и служат эталоном правил игры.

## `check_map.py`

Комплексный анализ **одной** карты: статика + симуляция игрового цикла + вердикт + маршрут.

На вход подаётся **полный путь** к `.txt` (параметр `--map`). Тема и `maps.json` не нужны.

### Запуск

```powershell
# эталон 100% победы
python tests/check_map.py --map "$PWD\tests\fixtures\win_100.txt"

# эталон 100% поимки
python tests/check_map.py --map "$PWD\tests\fixtures\fail_100.txt"

# случайный спавн мыши (микс побед/поимок)
python tests/check_map.py --map "$PWD\tests\fixtures\random_spawn.txt"

# реальная карта
python tests/check_map.py --map "$PWD\assets\maps\1\1.txt" --runs 100

# сохранить отчёт
python tests/check_map.py --map "$PWD\assets\maps\final.txt" --json report.json
```

Параметры: `--runs` (по умолчанию 100), `--seed`, `--dt` (1/60), `--R` (радиус реакции мыши,
по умолчанию 3), `--max-time` (180 c), `--json`, `--no-progress`.

Во время прогонов в `stderr` показывается прогрессбар `[####....] 42% (42/100)` (не мешает
основному отчёту в `stdout`); `--no-progress` его отключает.

> **Интерпретатор.** Используйте `python` или `py`. Команда `python3` на Windows часто указывает
> на заглушку Microsoft Store (путь `...\WindowsApps\python3.exe`), которая падает с
> «не удаётся найти указанный путь», если Python из Store не установлен.

Карта печатается сразу после строки `режим` (с маршрутом `*`, если найдена победа).

### Что проверяется

1. **Статика**: формат 16×32, периметр, допустимые символы, ровно 4 кота `A–D`, старт(ы) `+`,
   BFS-достижимость сыра/котов, изолированные области, тупики и мосты (артикуляционные точки),
   дистанции от старта. Сыр учитывается как в движке: цифры `1–9`, иначе старты котов `A–D`.
2. **Симуляция** — точный порт `GameScreen.updatePlaying` + `Cat`/`Mouse`: порядок кадра,
   скорости (мышь 150, коты 120; в `final` — 4 Chaser по 150), стратегии
   Chaser/Patrol/Random/Ambush, общая резервация клеток, запрет разворота/форс/тупик.
   Бот мыши идёт по BFS к ближайшему сыру, при коте ближе `R` — уходит от котов.
3. **Вердикт**: `ДА` при ≥1 победе (печатается маршрут лучшего прогона), `НЕТ` при 0 побед.
4. **Маршрут**: порядок сыра, путь по клеткам, команды (`LEFTx13`), ASCII-трасса, `seed`, время,
   запас до котов.

### Важно

- `НЕТ` — это «бот не нашёл победу», а **не** доказательство непроходимости. Бот жадный;
  при необходимости усилить (lookahead/поиск) — отдельная задача.
- Коды возврата: `0` — ДА, `1` — НЕТ или ошибка карты (удобно для CI).
- **Жизни/сердечки (`H`) чекер не моделирует**: симулируется **одна попытка без жизней**, и
  первая поимка = `CAUGHT`. В игре сердечко даёт +1 жизнь (до 7), а поимка с запасом ведёт к
  телепорту + неуязвимости. Поэтому оценка сложности карт чекером — **консервативная** (игра
  мягче), а `H` учитывается только как допустимый символ. Синхронизация симуляции с жизнями —
  отдельная задача (этап 15.3 решил не трогать чекер).
